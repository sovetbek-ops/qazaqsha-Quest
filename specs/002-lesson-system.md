# 002 — Система уроков

Статус: проект для утверждения. Реализация не начата; код можно менять только после команды «делай».

## Для кого и зачем

Для детей, начинающих изучать казахский язык. Пользователь должен видеть доступные уроки и понимать по каждому из них тему, сложность и прогресс прохождения.

Ожидаемый результат: на существующей странице появляется понятный список уроков, удобный для просмотра на телефоне. Эта спецификация описывает список и отображение прогресса; учебные задания пока отсутствуют.

## Что должно быть

### Список уроков

- На стартовой странице под существующим описанием размещается раздел «Уроки».
- Каждый урок отображается отдельной карточкой с названием, текстовой подписью уровня сложности и прогрессом.
- Все уроки из заданного в приложении списка видны без регистрации. Порядок соответствует порядку в данных; блокировки и условия открытия не добавляются.
- Название проекта, описание и сообщение «Учебные задания появятся позже» сохраняются: список не означает, что задания уже реализованы.
- Карточки служат для просмотра. Кнопки запуска и переходы к отсутствующим заданиям не добавляются.
- Если список пуст, вместо карточек показывается «Пока нет доступных уроков». Заголовок раздела остаётся видимым.

### Данные и начальное наполнение

Для каждого урока задаются отдельные данные: постоянный уникальный идентификатор, название, уровень сложности и прогресс в процентах. Положение карточки в списке не определяет её прогресс.

Предлагаемый начальный список для утверждения вместе со спецификацией:

| Название | Уровень сложности | Начальный прогресс |
| --- | --- | --- |
| Приветствия | Начальный | 0% |
| Цвета | Начальный | 0% |
| Числа | Начальный | 0% |

Это предложение по наполнению списка, а не согласованная учебная программа. Состав заданий и количество заданий в уроке здесь не определяются.

### Отображение прогресса

- В карточке видны подпись «Прогресс: N%» и полоса, заполненная пропорционально значению от 0 до 100. Значение доступно также средствам чтения с экрана.
- При 0% полоса пустая, при 100% — полная. Нулевое значение не заменяется прочерком и не считается отсутствующим.
- Прогресс одного урока не подставляется в другие карточки.
- В этой версии задания ещё не выполняются, поэтому начальный прогресс всех уроков равен 0%. Ненулевые значения из примеров используются только для проверки отображения и не показываются как реальные достижения ребёнка.
- Если прогресс отсутствует или не является целым числом от 0 до 100, показывается «Прогресс пока неизвестен» без числового индикатора. Отсутствие данных не выдаётся за 0%.
- При отсутствующем или состоящем только из пробелов названии показывается «Урок без названия», при таком же уровне — «Сложность не указана».
- Перезагрузка повторно отображает данные, заданные в приложении. Сохранение и изменение прогресса пользователем в эту версию не входят.

### Оформление и совместимость

- Сохраняется яркий стиль существующей страницы. Уровень и прогресс понятны по тексту, без необходимости различать цвета.
- Карточки имеют семантику списка, названия — понятную структуру заголовков.
- На ширинах 320, 375, 390, 768 и 1280 CSS-пикселей нет горизонтальной прокрутки, обрезания и наложения текста. Вертикальная прокрутка допустима.
- Длинные названия переносятся полностью, включая строки без пробелов. Русские и казахские буквы отображаются корректно.
- После поворота экрана и при увеличении текста до 200% все карточки остаются доступны.
- Список работает при локальном открытии `index.html`, без интернета, сервера и новых зависимостей.

## Примеры

Примеры ниже задают ожидаемое поведение. Проверочные значения не являются результатами реального пользователя.

| Условия | Ожидаемый результат |
| --- | --- |
| Первое открытие с предложенным начальным списком | Видны три карточки в указанном порядке; у каждой название, «Начальный» и «Прогресс: 0%», полоса пустая |
| У первого урока проверочный прогресс 40%, у второго 0%, у третьего 100% | Видны соответствующие проценты; полосы заполнены на 40%, на 0% и полностью; значения не смешиваются |
| Список уроков пуст | Видны «Уроки» и «Пока нет доступных уроков», пустых карточек нет |
| Название и уровень пустые или содержат только пробелы | Видны «Урок без названия» и «Сложность не указана» |
| Прогресс отсутствует, задан пустой строкой, равен −1, 101 или 12,5 | Видно «Прогресс пока неизвестен»; полоса с ложным значением не показывается |
| Название — текст длиной около 300 символов, строка из 100 букв без пробелов или «Ә Ғ Қ Ң Ө Ұ Ү Һ І» | Текст виден полностью, переносится и не перекрывает уровень и прогресс на ширине 320 |
| Название — строка «0», прогресс — число 0 | Название «0» и подпись «Прогресс: 0%» видны |
| Перезагрузка после временной подстановки проверочных данных в браузере | Восстанавливается начальный список с прогрессом 0%; временные значения не сохраняются |

## Ограничения

- Основа проекта проверена по `001-project-foundation.md`; настоящая спецификация расширяет стартовую страницу списком уроков. Остальные требования к основе сохраняются.
- Не добавляются учебные задания, запуск урока, оценка ответов, баллы, награды, фильтры, поиск, блокировки, авторизация и редактирование уроков пользователем.
- Расчёт прогресса по выполненным заданиям, его сохранение между посещениями и синхронизация требуют отдельных требований. Искусственно увеличивать прогресс нельзя.
- Русский язык подписей сохраняется как в текущей странице. Предложенное наполнение и способ отображения прогресса утверждаются вместе с этим документом.
- Код остаётся в `index.html`, `styles.css` и `script.js`. Новые зависимости и файлы тестов не создаются.
- README.md обновляется после последнего шага реализации, а не при подготовке этой спецификации.
- Каждый шаг выполняется отдельно после соответствующего указания пользователя. После проверки — остановка и вопрос «Коммитим?» по AGENTS.md. Ответ «да» разрешает только коммит и push, а не следующий шаг.

- [ ] Проверены 0%, промежуточное значение и 100%; числовые подписи соответствуют полосам и своим урокам.
- [ ] Пустой список, пустые поля, неизвестный прогресс и длинные значения отображаются по примерам.
- [ ] Пройдены проверки ширин, поворота, увеличения текста и казахских букв из раздела «Как проверить».
- [ ] Локальное открытие и перезагрузка без сети показывают исходные данные; в консоли нет ошибок приложения.
- [ ] Сохранены существующие тексты и оформление, отсутствуют элементы управления без действия.
- [ ] README.md описывает фактический список, смысл начального прогресса и ручную проверку.
- [ ] Записаны среда и результаты проверки; реальные Android, iPhone и Safari отмечены отдельно как проверенные или непроверенные.

## Как проверить

Проверки выполняются после реализации соответствующего шага. Для подстановки данных использовать временные изменения в браузере, например остановку перед построением списка в отладчике и изменение данных в текущем сеансе. Изменение только готового текста в Elements проверяет вёрстку, но не обработку данных. Проверочные данные не сохранять в исходные файлы; после каждого сценария восстанавливать исходное состояние перезагрузкой.

1. **Основной список.** Открыть `index.html` по инструкции README.md. Сверить порядок, названия, уровни и 0% с утверждённым списком. Убедиться, что существующие три текста сохранены и карточки не обещают запуск заданий.
2. **Границы прогресса.** Временно передать трём урокам 40, 0 и 100. Проверить числовые подписи, независимость карточек и заполнение полос. Проверить, что средства чтения с экрана или дерево доступности браузера получают название урока и значение прогресса.
3. **Пустые и некорректные данные.** Подставить пустой список; проверить сообщение. Затем подставить урок с пустыми названием и уровнем, повторить с пробелами. По очереди проверить отсутствующий прогресс, пустую строку, −1, 101 и 12,5: ожидаются подстановочные подписи из примеров. Отдельно проверить название «0» и прогресс 0.
4. **Длинный текст и буквы.** Подставить названия из примеров: около 300 символов, 100 букв без пробелов и казахские буквы. На ширине 320 проверить полный перенос, читаемость и отсутствие наложений.
5. **Телефон и увеличение.** В режиме Responsive проверить ширины 320, 375, 390, 768 и 1280, затем поменять ширину и высоту местами. На ширине 320 временно задать для `html` размер шрифта 200%, как в README.md. Все карточки должны оставаться доступны без горизонтальной прокрутки.
6. **Перезагрузка и работа без сети.** После временных подстановок включить Offline в инструментах браузера и перезагрузить локальную страницу. Должны восстановиться согласованные исходные данные, оформление и 0%. Проверить загрузку CSS и JavaScript и отсутствие ошибок приложения в Console; вернуть обычный режим сети.
7. **Реальные устройства и документация.** При наличии устройств проверить список в Chrome на Android и Safari на iPhone по доступному адресу предпросмотра, в двух ориентациях и с увеличением. Записать версии и адрес; при отсутствии устройств явно отметить ограничение. Сверить README.md с итоговым экраном и повторить применимые проверки основы из его раздела «Как проверить».

## Шаги

### [ ] 1. Список, названия и уровни

На экране: раздел «Уроки» с карточками согласованного списка, названиями и уровнями сложности; при пустом списке — понятное сообщение. Существующее содержимое сохраняется. Отображение прогресса добавляется следующим шагом.

Ручная проверка:

1. Открыть страницу и сверить список с утверждёнными данными.
2. Временно подставить пустой список, затем пустые название и уровень; проверить соответствующие сообщения.
3. Перезагрузить страницу: исходный список и существующие тексты восстановлены, ошибок приложения нет.

### [ ] 2. Отображение прогресса

На экране: у каждой карточки появляются процент и полоса прогресса, а при отсутствии корректного значения — подпись «Прогресс пока неизвестен».

Ручная проверка:

1. Проверить начальные 0%, затем временно подставить разным урокам 40%, 0% и 100%; сверить подписи, полосы и доступные значения.
2. Проверить отсутствующие и некорректные значения по примерам; убедиться, что они отличаются от настоящего 0%.
3. Перезагрузить страницу: все уроки снова показывают начальные 0%.

### [ ] 3. Мобильная адаптация, итоговая проверка и README

На экране: полный список с читаемыми карточками на узких и широких экранах, включая длинные названия и увеличенный текст. README.md описывает фактический результат и способы проверки.

Ручная проверка:

1. Проверить размеры, поворот, увеличение и длинные значения по пунктам 4–5 раздела «Как проверить».
2. Проверить перезагрузку без сети и консоль по пункту 6; при наличии реальных телефонов выполнить пункт 7 и отдельно записать ограничения.
3. Выполнить оставшиеся проверки, сверить все пункты «Готово, когда» и актуальность README.md. Отмечать пункты только по фактическим результатам.
