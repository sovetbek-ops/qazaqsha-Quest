## Для кого и зачем

qazaqsha Quest — обучающая игра для детей, начинающих изучать казахский язык. Первый этап создаёт понятный стартовый экран и техническую основу для последующих согласованных функций.

Результат этапа — статическая страница, которую можно открыть локально и удобно просматривать на телефоне и компьютере.

## Что должно быть

```text
qazaqsha Quest/
├── AGENTS.md
├── README.md
├── index.html
├── styles.css
├── script.js

    └── 001-project-foundation.md
```

- `AGENTS.md` — существующие правила работы; не изменяется в рамках этапа.
- `README.md` — описание проекта; после последнего шага дополняется фактическими возможностями и инструкцией запуска и проверки.
- `index.html` — разметка единственного стартового экрана.
- `styles.css` — оформление страницы и адаптация к размеру экрана.
- `script.js` — подключённый файл для будущей логики; на этом этапе игрового поведения нет.
- `specs/` — требования к функциям и отметки о выполненных шагах.

Дополнительные папки и файлы на первом этапе не требуются.

### Начальная архитектура

Приложение — одна статическая веб-страница на HTML, CSS и обычном JavaScript, без библиотек, сборки и серверной части.

`index.html` подключает `styles.css` и `script.js` относительными путями. JavaScript подключается так, чтобы не мешать загрузке разметки. Стили размещаются в CSS, будущая логика — в JavaScript.

Страница использует UTF-8 для корректного отображения русских и казахских букв. Язык документа соответствует основному языку текста. Разметка содержит основной заголовок и область основного содержимого.

На экране отображаются:

- Название «qazaqsha Quest».
- Краткое описание: «Игра для первых шагов в казахском языке».
- Честное сообщение о состоянии: «Учебные задания появятся позже».

Переходы между экранами, игровые задания, кнопки без действия и хранение данных в этот этап не входят. Перезагрузка возвращает тот же стартовый экран.

### Адаптация под Android и iPhone

Целевой формат — веб-страница в Chrome на Android и Safari на iPhone. Отдельные приложения для магазинов не создаются.

Требования:

- Ширина страницы соответствует ширине экрана устройства; масштабирование пользователем доступно.
- Интерфейс строится сначала для узкого экрана и расширяется для планшетов и компьютеров.
- На ширинах 320, 375, 390, 768 и 1280 CSS-пикселей нет горизонтальной прокрутки, обрезания и наложения текста.
- При повороте телефона содержимое остаётся доступным; вертикальная прокрутка допустима.
- Текст не попадает под вырезы экрана и системные области, если страница занимает такую область.
- Основной текст имеет размер не менее 16 CSS-пикселей; на компьютере строки ограничены по ширине для удобства чтения.
- Оформление яркое, текст хорошо различим на фоне; смысл не передаётся одним цветом.
- Для просмотра страницы не нужны наведение мыши и точные касания.
- При увеличении текста до 200% содержимое остаётся читаемым и доступным.

Проверки в эмуляции мобильной ширины и на реальных устройствах фиксируются отдельно. Точные версии браузеров записываются при проверке; поддержка всех старых версий не предполагается.

### Локальный запуск

После реализации файлов:

1. Открыть папку проекта в проводнике.
2. Открыть `index.html` в браузере двойным щелчком или через «Открыть с помощью».
3. Убедиться, что виден оформленный стартовый экран.

Установка библиотек, сборка, интернет и локальный сервер для этого этапа не требуются. Используются локальные файлы без внешних шрифтов, изображений и сетевых запросов.

Открытие файла на компьютере не является проверкой на реальном телефоне. Для проверки на телефонах можно использовать доступный предпросмотр проекта по HTTP; способ доступа и адрес фиксируются в отчёте, если такая проверка проведена. Настройка хостинга в этап не входит.

## Примеры

- При открытии `index.html` на компьютере пользователь видит название, описание и сообщение о будущих заданиях.
- На узком экране описание переносится на строки, а содержимое помещается по ширине.
- После обновления страницы экран остаётся тем же; ошибок загрузки подключённых файлов нет.
- Русский текст и проверочная строка «Ә Ғ Қ Ң Ө Ұ Ү Һ І» отображаются без искажений. Проверочная строка используется временно при проверке и не становится частью экрана.

## Ограничения

- Сейчас создаётся только эта спецификация. Код пишется после утверждения и команды «делай».
- Реализуется один шаг за раз. После выполнения и проверки шага работа останавливается для проверки пользователем и решения о коммите.
- Команда «да» после вопроса «Коммитим?» разрешает коммит и push по AGENTS.md, но не следующий шаг реализации.
- Не добавляются задания, баллы, звук, авторизация, сохранение прогресса, маршрутизация и установка на телефон.
- Не устанавливаются зависимости и не создаются новые файлы тестов.
- README.md изменяется только после последнего шага реализации. При подготовке спецификации существующие файлы не меняются.
